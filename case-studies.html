BUILD NOTES, NOT MARKETING CLAIMS

What each demo proves — and what would change in production.

All four portfolio projects are self-initiated demos. This page separates what is actually implemented from the production architecture I would use for a client project.

01
Conversion web

Service landing page + lead capture

A responsive acquisition page with a working form, client-side validation and an observable submission event.

Brief

Create a simple service website that makes the primary conversion action obvious on both mobile and desktop.

Implemented

  • Responsive layout
  • CTA navigation
  • Required-field validation
  • Lead payload creation
  • Visible event log

Production extension

  • POST lead to CRM/API
  • Server-side validation
  • Spam protection
  • Analytics events
  • Transactional notification

Acceptance test

  • Works at 390px and desktop
  • Empty form cannot submit
  • Payload contains required fields
  • User receives success state
Browser form→Validation→Webhook/API→CRM→Notification

02
Qualification flow

AI-ready lead qualification assistant

The demo intentionally uses deterministic JavaScript rather than pretending to call an AI model. It shows the interaction and structured-output layer.

Brief

Collect useful sales context without making the user fill a long static form.

Implemented

  • Multi-step state flow
  • Dynamic answer choices
  • Lead object creation
  • Qualification label
  • JSON-style summary

Production extension

  • LLM API for free-text input
  • Guardrails / system prompt
  • CRM create/update
  • Human handoff
  • Conversation logging

Acceptance test

  • Each choice advances state
  • All answers appear in summary
  • Reset returns clean state
  • No hidden external data transfer
User→Conversation UI→LLM / rules→Structured lead→CRM

03
Automation

Observable lead-routing workflow

A workflow simulator designed to make automation logic visible instead of hiding it behind a black box.

Brief

Show how one inbound lead can move through validation, CRM creation, ownership assignment and follow-up.

Implemented

  • Five workflow states
  • Sequential transitions
  • Event log
  • Run/reset controls
  • Visible completion state

Production extension

  • Webhook trigger
  • Retry/error handling
  • CRM API calls
  • Queue for async jobs
  • Alerting and audit log

Acceptance test

  • Stages run in order
  • Log matches stage state
  • Button locks during run
  • Workflow can be run again
Trigger→Validate→CRM action→Assignment→Follow-up

04
Internal web app

Interactive lead CRM dashboard

This demo goes beyond a landing page: it keeps application state, calculates live KPIs and persists changes in the browser.

Brief

Give a small sales team one interface to create leads, search records, change stages and monitor pipeline totals.

Implemented

  • Create lead
  • Search + stage filter
  • Stage updates
  • Pipeline totals
  • Local persistence
  • Reset demo dataset

Production extension

  • REST backend
  • PostgreSQL / managed DB
  • User authentication
  • Role permissions
  • Server validation
  • Audit log

Acceptance test

  • Added leads appear immediately
  • KPIs recalculate
  • Filters combine correctly
  • State survives refresh
  • Reset restores demo data
Web app→REST API→Auth→Database→Integrations
